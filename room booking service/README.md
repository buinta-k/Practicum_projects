# Бронирование комнат

REST API на Go для бронирования комнат: можно создавать комнаты, бронировать их на даты, отменять брони и искать комнаты, свободные на нужный период. В комплекте простой веб-интерфейс с календарём занятости.

## Стек

- Go 1.26, стандартный `net/http` (роутинг через `ServeMux` с методами и параметрами пути)
- SQLite (драйвер [`modernc.org/sqlite`](https://pkg.go.dev/modernc.org/sqlite), без CGO)
- Фронтенд: HTML, CSS, JavaScript без фреймворков

## Запуск

```bash
git clone <ссылка-на-репозиторий>
cd <папка-проекта>
go run .
```

Откройте http://localhost:3000.

При первом запуске база `demo.db` создаётся автоматически по схеме из `init.sql`. Запускать нужно из корня проекта.

## API

Даты передаются в формате `YYYY-MM-DD`. Бронь занимает период `[start_at, end_at)`: день выезда считается свободным, как в отелях.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/rooms` | Список комнат |
| `POST` | `/rooms` | Создать комнату |
| `GET` | `/rooms/available?start_at=…&end_at=…` | Комнаты, свободные на весь период |
| `GET` | `/bookings?room_id=…` | Активные брони комнаты |
| `POST` | `/bookings` | Создать бронь |
| `DELETE` | `/bookings/{id}` | Отменить бронь |

### Примеры

Создать комнату:

```bash
curl -X POST localhost:3000/rooms -d '{"name": "Гостиная"}'
# {"id":1,"name":"Гостиная"}
```

Забронировать:

```bash
curl -X POST localhost:3000/bookings \
  -d '{"room_id": 1, "start_at": "2026-11-10", "end_at": "2026-11-12"}'
# {"id":1}
```

Если комната на эти даты уже занята, сервер ответит `409 Conflict`:

```json
{"error": "room is already booked for these dates"}
```

Найти свободные комнаты:

```bash
curl "localhost:3000/rooms/available?start_at=2026-11-11&end_at=2026-11-13"
# [{"id":2,"name":"Спальня"}]
```

Отменить бронь:

```bash
curl -X DELETE localhost:3000/bookings/1
# {"id":1}
```

Ошибки возвращаются в виде `{"error": "описание"}` с соответствующим HTTP-кодом: `400`, `404`, `409` или `500`.

## Как это устроено

- **Проверка пересечений.** Два периода пересекаются, если `старая.начало < новая.конец` и `старая.конец > новая.начало`. Проверка и вставка брони выполняются в одной транзакции.
- **Отмена — мягкое удаление.** Бронь не удаляется из базы, а помечается флагом `cancelled`. Отменённые брони не мешают новым и не показываются в списках.
- **Поиск свободных комнат** — один SQL-запрос с `NOT EXISTS`: выбираются комнаты, у которых нет ни одной активной брони, пересекающейся с запрошенным периодом.
